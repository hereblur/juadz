Routing and List Queries

The Fastify integration generates routes from the operations implemented by each provider. By default, a resource named users has:

MethodPathPurpose
GET/usersList records
GET/users/:idRead one record
POST/usersCreate a record
PATCH/users/:idUpdate fields
PUT/users/:idReplace a record
DELETE/users/:idDelete a record

A plugin prefix is added to those paths. For example, registering the plugin with prefix: "/api/v1" exposes /api/v1/users.

Custom route providers​

A RouterProvider receives an action and resource name, then returns a { path, method } definition or null to suppress that generated route:

import type { RouterProvider } from "@juadz/core";

const routes: RouterProvider = (action, resourceName) => {
  if (action === "replace") return null;

  if (action === "list" || action === "create") {
    return {
      path: `${resourceName}/archive`,
      method: action === "list" ? "GET" : "POST",
    };
  }

  return {
    path: `${resourceName}/:id`,
    method:
      action === "get" ? "GET" :
      action === "update" ? "PATCH" :
      action === "delete" ? "DELETE" : "PUT",
  };
};

usersResource.setRouterProvider(routes);

A custom provider replaces the default mapping for every generated action, so handle all actions your provider supports. For one-off endpoints, use Fastify routes or add a ResourceEndpoint instead of forcing them into the standard CRUD mapping.

Default list query syntax​

The default list adaptor accepts these query parameters:

GET /api/v1/users?filter=status:active&limit=20&offset=0&sort=-createdAt
  • filter is a comma-separated list of field:value equality filters.
  • limit defaults to 10; offset defaults to 0.
  • sort accepts a field name for ascending order or a - prefix for descending order.
  • Free-text filtering and sorting are restricted by schema metadata and the database adapter.

For a filter to take effect in Knex or Mongo, mark its field $filter: true. Mark sort fields with $sort: true; mark text-search fields with $search: true. Do not assume every adapter supports every filter operator. The default query parser supports equality filters; custom adaptors can expose richer syntax.

List responses contain the record array in the body and report the total count in an X-total-<resourceName> header, for example X-total-users: 42.

Custom list adaptor​

A QueryListAdaptor<T> translates HTTP input into the common QueryListParam shape and formats the provider result. It must implement parser, response, and params; optional Zod schemas describe the HTTP contract to documentation tooling.

usersResource.setListAdaptor(myListAdaptor);

The parser receives (resource, query, params, body, headers). Its result is passed to preList hooks and the provider. The response function receives { data, total }, the parsed query, and the resource name. Ensure custom adaptors validate and constrain client input before it reaches your provider.

Extra endpoints​

Use Fastify's normal route registration for application workflows that do not fit CRUD, or register a typed ResourceEndpoint using the resource's route extension API. Keep authorization checks explicit for those routes; generated resource permissions do not automatically protect unrelated Fastify handlers.
